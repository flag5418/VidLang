# Skill: 修复 Bug

> **版本**: V1.0 | **日期**: 2026-07-12
> **触发条件**: 当用户要求修复 Bug 时

---

## 一、工作流

### 1.1 分析阶段

- [ ] 1. 理解 Bug 描述
- [ ] 2. 复现 Bug
- [ ] 3. 分析根本原因
- [ ] 4. 评估影响范围
- [ ] 5. 制定修复方案

### 1.2 修复阶段

- [ ] 1. 实现修复代码
- [ ] 2. 编写测试用例
- [ ] 3. 验证修复效果
- [ ] 4. 检查代码规范
- [ ] 5. 更新文档

### 1.3 验证阶段

- [ ] 1. 运行所有测试
- [ ] 2. 检查回归问题
- [ ] 3. 更新知识库
- [ ] 4. 提交代码

---

## 二、检查清单

### 2.1 Bug 分析

- [ ] 理解 Bug 描述
- [ ] 复现 Bug 步骤
- [ ] 分析根本原因
- [ ] 评估影响范围
- [ ] 制定修复方案

### 2.2 修复代码

- [ ] 修复代码符合规范
- [ ] 修复代码有完整注释
- [ ] 修复代码有测试覆盖
- [ ] 修复代码不影响其他功能

### 2.3 测试验证

- [ ] 编写测试用例
- [ ] 测试用例覆盖边界情况
- [ ] 测试用例可重复执行
- [ ] 测试用例结果正确

### 2.4 文档更新

- [ ] 更新 Bug 记录
- [ ] 更新知识库
- [ ] 提交 Commit

---

## 三、知识库加载

### 3.1 自动加载

- `overall-architecture.md` - 整体架构
- `flutter-code-structure.md` - 代码结构

### 3.2 按需加载

- `database-design.md` - 数据库设计（当 Bug 涉及数据库时）
- `services-architecture.md` - 服务架构（当 Bug 涉及服务层时）

## 四、输出格式

### 4.1 代码输出

```dart
// Bug 修复代码
// 包括：修复代码、测试用例
```

### 4.2 文档输出

```markdown
# Bug 修复说明

## Bug 描述
[Bug 描述]

## 根本原因
[根本原因]

## 修复方案
[修复方案]

## 测试验证
[测试验证结果]

## 影响范围
[影响范围]
```

---

## 五、注意事项

1. **彻底分析**：必须找到根本原因，不能只修复表面现象
2. **测试覆盖**：必须编写测试用例，防止 Bug 再次出现
3. **回归测试**：必须检查修复是否影响其他功能
4. **文档完整**：必须更新 Bug 记录和知识库
