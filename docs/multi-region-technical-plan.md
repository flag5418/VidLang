# VidLang 多国家/地区上架技术方案

> **版本**: v1.0 | **日期**: 2026-07-07  
> **关联**: n18 年龄分级 + 多语言适配 + 支付集成

---

## 一、核心结论

### 1.1 支付方案简化

| 平台 | 方案 | 说明 |
|------|------|------|
| **iOS** | Apple IAP | 统一价格，Apple 处理货币转换和收款 |
| **Android (Play Store)** | Google Play Billing | 统一价格，Google 处理货币转换和收款 |
| **Android (APK 侧载)** | 支付宝 H5 | 备选方案，仅国内用户 |

**关键认知**：App Store 和 Google Play 已经有完整的价格体系，我们只需要：
1. 配置 Product ID + 基准价格（如 ¥10/¥50/¥100）
2. 平台自动处理：货币转换、税率计算、收款、退款
3. 我们只负责：收据验证 + 发货（增加用户余额）

### 1.2 年龄分级建议

| 分级 | 推荐度 | 说明 |
|------|--------|------|
| **4+** | ⭐⭐⭐ 强烈推荐 | 适合所有年龄，最大化用户覆盖 |
| **9+** | ⭐⭐ 可选 | 如有轻微暴力/幻想内容 |
| **12+** | ⭐ 不推荐 | 教育类应用不需要 |
| **18+** | ❌ 不推荐 | 严重限制用户获取和可见性 |

### 1.3 多语言优先级

| 语言 | 优先级 | 市场 |
|------|--------|------|
| 中文简体 | P0 | 中国 |
| 英文 | P0 | 全球 |
| 中文繁体 | P1 | 台湾/香港 |
| 日文 | P2 | 日本 |
| 韩文 | P2 | 韩国 |
| 其他 | P3 | 按需扩展 |

## 二、与 n18 的关联分析

### 2.1 什么是 n18

"n18" 通常指 **18+ 年龄分级**，即应用包含仅适合成人观看的内容。

### 2.2 VidLang 是否需要 n18

```
┌─────────────────────────────────────────────────────────────────┐
│                    VidLang 内容评估                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ✅ 不包含 18+ 内容:                                            │
│     ├─ 无暴力/恐怖内容                                          │
│     ├─ 无色情/成人内容                                          │
│     ├─ 无赌博/博彩功能                                          │
│     ├─ 无烟酒/毒品相关内容                                      │
│     ├─ 无粗俗语言                                               │
│     └─ 无真实世界金融交易风险                                   │
│                                                                 │
│  📚 教育类应用特征:                                             │
│     ├─ 目标用户: 学生/语言学习者                                │
│     ├─ 内容: 视频学习、字幕、跟读、查词                        │
│     └─ 分级: 4+ 适合所有年龄                                    │
│                                                                 │
│  🎯 结论: 不需要 18+，应该选择 4+                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 如果选择 18+ 的后果

| 影响 | iOS | Android |
|------|-----|---------|
| **可见性** | 在搜索/推荐中被降权 | 在搜索/浏览中被过滤 |
| **家长控制** | 被 Screen Time 屏蔽 | 被 Family Link 屏蔽 |
| **下载限制** | 未成年人需家长授权 | 18岁以下无法下载 |
| **广告** | 可能无法投放某些广告 | 受限于 Families Policy |
| **品牌** | 影响专业教育形象 | 同上 |

## 三、与多语言适配的关联

### 3.1 多语言 vs 年龄分级

```
多语言适配本身不影响年龄分级，但会影响：

1. 地区合规要求
   ├─ 中国: ICP 备案 + 内容审核
   ├─ 欧盟: GDPR + Cookie 同意
   └─ 其他: 各国隐私法

2. 分级机构
   ├─ ESRB (美洲)
   ├─ PEGI (欧洲)
   ├─ CERO (日本)
   ├─ GRAC (韩国)
   └─ IARC Generic (其他)

3. 本地化内容
   └─ 如有用户生成内容，需审核机制
```

### 3.2 推荐方案

```
阶段 1: 最小化多语言
        └─ 中文简体 + 英文 (覆盖 90% 用户)
        
阶段 2: 扩展亚洲市场
        └─ + 中文繁体 + 日文 + 韩文
        
阶段 3: 全球化
        └─ + 西班牙语 + 葡萄牙语 + 法语 + 德语
```

## 四、与支付的关联

### 4.1 支付体系对比

| 特性 | 旧方案 (复杂) | 新方案 (简化) |
|------|---------------|---------------|
| 多币种定价 | 自己维护定价表 | 平台自动处理 |
| 汇率转换 | 需要实现 | 平台自动处理 |
| 税率计算 | 需要实现 | 平台自动处理 |
| 收款 | 自己对接支付渠道 | 平台统一收款 |
| 退款 | 自己处理 | 平台处理 |

### 4.2 简化后的支付架构

```
┌─────────────────────────────────────────────────────────────────┐
│                    简化后的支付流程                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  App Store / Google Play                                        │
│  ├─ 用户选择充值档位 (¥10/¥50/¥100)                           │
│  ├─ 平台自动转换货币 (如 $1.5/$7.5/$15)                        │
│  ├─ 平台处理支付 (信用卡/Apple Pay/Google Pay)                 │
│  └─ 返回收据 (Receipt)                                         │
│                                                                 │
│  我们的 Edge Function                                          │
│  ├─ 接收购据                                                   │
│  ├─ 调用平台 API 验证收据                                      │
│  ├─ 验证通过 → 增加用户余额                                   │
│  └─ 返回成功                                                   │
│                                                                 │
│  用户余额                                                      │
│  └─ 全部以人民币 (¥) 存储和显示                               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.3 不需要实现的功能

| 功能 | 原因 |
|------|------|
| ❌ 多币种定价表 | 平台自动处理汇率 |
| ❌ 汇率转换 API | 平台自动处理 |
| ❌ 税率计算 | 平台自动处理 |
| ❌ 支付渠道对接 | 平台统一收款 |
| ❌ 地区支付方式适配 | 平台支持当地支付方式 |

### 4.4 需要实现的功能

| 功能 | 说明 |
|------|------|
| ✅ 收据验证 | 调用 Apple/Google API 验证 |
| ✅ 余额管理 | 存储用户充值余额 (人民币) |
| ✅ 消费扣费 | AI 功能调用时扣费 |
| ✅ 历史记录 | 充值/消费记录查询 |

## 六、关键决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 年龄分级 | 4+ | 教育类应用，最大化用户覆盖 |
| 支付方案 | 平台 IAP | 简单，平台处理复杂逻辑 |
| 余额存储 | 人民币 | 统一计价，避免汇率问题 |
| 多语言 | 中+英优先 | 覆盖主要市场，后续扩展 |
| 法律合规 | 优先中国+美国 | 最大市场，其他按需 |
