# VidLang 详细设计 — 音频学习系统

> 版本：v1.0  
> 更新日期：2026-06-15  
> 设计范围：纯音频(pure) + 音乐(music) 统一学习体系  
> 核心理念：导入只管存，打开才识，识不到就听，识到了就学，学着要快乐

---

## 一、设计哲学

### 1.1 五个核心原则

```
1. 延迟识别：导入时不做AI识别，打开时才提示，传输模块零改动
2. 优雅降级：AI识别不到就礼貌告知，转入欣赏模式，绝不卡住用户
3. 快乐学习：中文注音让用户30秒内能跟着哼出来，即时成就感
4. 多语言支持：声通多语言评分 + 千问多语言翻译注音，不局限于英语
5. 数据驱动：评分体系 + AI评价 + 学习记录，让工具变成有价值的亮点
```

### 1.2 两种音频类型

| 维度 | 纯音频(pure) | 音乐(music) |
|------|-------------|-------------|
| 场景 | 听力训练、考试备考 | 学唱歌曲、趣味学习 |
| 字幕来源 | 用户上传 / AI语音识别 / AI纠正翻译 | 用户上传 / AI搜歌词 / AI语音识别(降级) |
| 无字幕时 | 提示智能识别或手动导入 | 提示智能匹配或手动导入，找不到则欣赏模式 |
| 特有功能 | 听力测试(AI出题) | 中文注音(辅助发音) |
| 跟读用词 | "跟读" | "跟唱" |

### 1.3 与现有设计的关系

本文档替代 `03-music-design.md` 中关于"录音不降音量"的结论。新方案为：**跟读/跟唱时原音音量可调（0%-100%），耳机模式下录音数据纯净，统一体验。**

## 二、导入阶段 — 零改动原则

### 2.1 导入时不做任何AI调用

```
WiFi传输 / 本地导入 / 文件选择器 → 完全不改

唯一处理：
- 文件存入应用目录
- 提取时长(已有 VideoMetadataExtractor)
- 创建 VideoInfo 记录
- 封面：无封面时用标题首字母生成占位图
- hasSubtitles = 检测到字幕文件 ? true : false
```

### 2.2 首字母封面生成

```
┌─────┐   ┌─────┐   ┌─────┐
│  L  │   │  Y  │   │  中  │
│     │   │     │   │     │
└─────┘   └─────┘   └─────┘
Let It Be  Yesterday  中文歌

实现：Canvas绘制圆形/方形渐变背景 + 居中首字母
颜色按文件名hash选取，不需要网络，不需要API
存入 VideoInfo.cover 字段，与视频缩略图存储方式一致
```

## 三、打开阶段 — 字幕获取流程

### 3.1 无字幕提示弹窗

用户打开一个无字幕音频时弹出：

```
┌──────────────────────────────────────────────────┐
│  🎧 该资源暂无字幕                                    │
│                                                       │
│  没有字幕也能播放欣赏                                  │
│  添加字幕后可解锁：跟读评分、划词查义、翻译等学习功能  │
│                                                       │
│  ┌─────────────────┐  ┌─────────────────┐           │
│  │ 🤖 智能匹配字幕  │  │ 📄 手动导入字幕  │           │
│  │ AI自动识别并生成 │  │ 上传SRT/LRC文件  │           │
│  └─────────────────┘  └────────────────┘           │
│                                                       │
│  ┌──────────────────────────────────────┐          │
│  │ 🎵 先欣赏模式                          │          │
│  │ 暂不添加字幕，直接播放                  │          │
│  └──────────────────────────────────────┘          │
└───────────────────────────────────────────────────┘
```

用户选择后：
- **手动导入** → 文件选择器 → SRT/LRC解析 → 存入DB → 上传Supabase
- **智能匹配** → 根据audioType走不同路径（见3.2/3.3）
- **先欣赏** → 进入纯播放器模式，后续可在设置中触发智能匹配

### 3.2 纯音频的智能匹配

```
┌──────────────────────────────────────┐
│  🔄 正在识别音频内容...                 │
│                                        │
│  上传音频到边缘函数，调用千问语音识别     │
│                                        │
│  ████████░░░░ 60%                      │
│                                        │
│  识别期间您可以继续收听                  │
│  [取消]                                 │
└───────────────────────────────────────┘

边缘函数一次性完成：
  ① 千问语音识别 → 带时间戳的英文文本(句级)
  ② AI纠正 → 语法/拼写修正
  ③ AI翻译 → 逐句中文翻译
  ④ 语言检测 → 识别音频语言(英语/法语/日语/...)
  ⑤ 中文注音 → 生成汉字谐音标注

客户端收到结果后：
  → 写入 Subtitles 表 (source='ai_recognize')
  → 写入 Participle 表
  → 更新 VideoInfo.language / hasSubtitles
  → uploadSubtitlesToCloud()
  → 刷新播放器，解锁学习功能

识别失败：
  ⚠️ 未能识别此音频内容
  可能原因：音频质量不佳/时长过短/含噪声
  当前已转入欣赏模式
  [重试识别] [手动导入字幕] [继续收听]
```

### 3.3 音乐的智能匹配

```
第1步：提取MP3文件ID3标签（本地，零成本）

  解析文件内嵌信息:
  - title  → 歌曲名
  - artist → 演唱者
  - album  → 专辑名
  - APIC   → 封面图(base64 → 保存为本地文件)

  有 title + artist → 直接进入第2步
  无有效标签 → 弹出输入框：

  ┌───────────────────────────────┐
  │ 请输入歌曲信息以便搜索歌词       │
  │                                 │
  │ 歌曲名: [___________]          │
  │ 演唱者: [___________]          │
  │                                 │
  │ [搜索歌词]  [跳过,先欣赏]       │
  └────────────────────────────────┘

第2步：调用边缘函数搜索歌词

  请求: { type: 'lyrics_search', title, artist, includePronunciation: true }

  边缘函数逻辑：
  ① 千问搜歌词 → 成功 → 返回歌词+翻译+注音+封面URL
  ② 千问搜不到 → 尝试上传音频片段让千问语音识别(降级)
  ③ 全部失败 → 返回 { ok: false }

  成功后客户端处理：
  → 封面图: 从ID3提取 或 边缘函数返回的URL下载
  → 更新 VideoInfo: artist, album, cover, language, hasSubtitles
  → 写入 Subtitles 表 (source='ai_lyrics_search')
  → 写入 Participle 表
  → uploadSubtitlesToCloud()
  → 刷新播放器，解锁学习功能

  失败：
  ⚠️ 未能找到该歌曲的歌词
  很抱歉，暂时无法自动匹配
  当前已转入欣赏模式
  [手动导入LRC/SRT] [继续欣赏音乐]
```

### 3.4 边缘函数设计

```
新增边缘函数: ai-audio-recognize

统一入口，根据请求type走不同逻辑：

请求格式:
{
  type: 'speech_recognize' | 'lyrics_search',

  // === lyrics_search 参数 ===
  title: String,
  artist: String?,
  includePronunciation: Boolean,

  // === speech_recognize 参数 ===
  audioBase64: String?,
  audioUrl: String?,
  includePronunciation: Boolean,
}

返回格式:
{
  ok: Boolean,
  language: String,  // 'en'|'fr'|'ja'|'ko'|... 自动检测
  title: String?,    // 歌曲名(音乐)
  artist: String?,   // 演唱者(音乐)
  coverUrl: String?, // 封面URL(音乐)
  items: [{
    content: String,           // 原文
    contentTranslate: String?, // 翻译(法语等非英语→中文翻译，英语→中文翻译)
    startMs: int?,             // 起始时间(毫秒，可能为null)
    endMs: int?,               // 结束时间(毫秒，可能为null)
    pronunciation: String?,    // 中文注音(整行)
    pronunciationMap: [{       // 逐词注音(可选)
      word: String,
      zh: String
    }]?
  }],
  source: 'ai_recognize' | 'ai_lyrics_search'
}

计费: 统一走 ai-proxy 的 billing 体系
```

## 四、字幕上云 — 统一规则

### 4.1 同步时机

字幕数据任何变更后自动上传到Supabase（与视频一致）：

| 时机 | 触发方式 |
|------|---------|
| 手动导入字幕后 | FilePickerService._importSubtitle 末尾 |
| AI识别/搜索成功后 | 识别完成回调中调用 |
| 用户编辑修正字幕后 | 编辑保存后调用 |
| 用户跟读评分后(补充词级时间戳) | 评分完成回调中调用 |

### 4.2 上云的价值

- AI出题需要云端字幕（边缘函数直接读取）
- AI对话需要云端字幕（已实现）
- AI评价需要云端字幕（新增）
- 跨设备同步
- 用户间歌词共享（同一首歌，别人已校对过）

### 4.3 存储格式扩展

现有 `subtitle-storage` Edge Function 的 items 结构扩展：

```json
{
  "video_code": "...",
  "title": "...",

  "language": "en",
  "items": [{
    "start_position": 0,
    "end_position": 5000,
    "content": "I want to hold your hand",
    "content_translate": "我想牵着你的手",
    "source": "ai_lyrics_search",
```

## 五、多语言支持

### 5.1 语言检测与标注

```
AI识别/搜索时自动检测音频语言，存入 VideoInfo.language

翻译策略：
  英语 → 中文翻译
  法语 → 原样输出法语 + 中文翻译
  日语 → 原样输出日语 + 中文翻译
  韩语 → 原样输出韩语 + 中文翻译
  其他语言 → 同理

核心原则：用户是中国人，始终提供中文翻译作为理解辅助
          原文保留，因为用户需要看到原文来学习/跟读
```

### 5.2 声通多语言评分

```
声通官方支持多语言评测，调用时需指定语言对应的coreType：

| 语言   | coreType           | 说明            |
|--------|--------------------|-----------------|
| 英语   | en.sent.eval       | 已确认支持      |
| 法语   | fr.sent.eval       | 官方支持        |
| 日语   | ja.sent.eval       | 官方支持        |
| 韩语   | ko.sent.eval       | 官方支持        |
| 其他   | 需确认声通文档      | 按需扩展        |

调用方式：
  ShengtongEvaluator.connect('{language}.sent.eval')
  ShengtongEvaluator.start(
    coreType: '{language}.sent.eval',
    refText: currentSubtitleContent,
    userId: userCode,
  )

不支持的语言：跟读评分功能隐藏，仅保留聆听+注音+翻译
```

### 5.3 中文注音的跨语言适配

```
千问生成注音时，根据语言使用不同的注音策略：

英语: "I want to hold your hand" → "爱 旺特 兔 厚的 尤尔 汉德"
日语: "さくら さくら" → "撒库拉 撒库拉"
韩语: "사랑해" → "撒浪嘿"
法语: "Je t'aime" → "热 泰姆"

注音规则（在千问prompt中指定）：
1. 用常见汉字标注，选择声调最接近的汉字
2. 每个词/字对应一组汉字
3. 这是辅助工具，不求完全精确，只求快速上手
4. 目标：让中文母语者30秒内能近似发音
```

## 六、中文注音 — 杀手级功能

### 6.1 核心价值

```
痛点：
- 中国用户学外文歌，最大障碍是发不出那个音
- 看着歌词，知道意思，但嘴巴跟不上
- 传统方法：反复听模仿 → 效率极低 → 挫败感 → 放弃

中文注音的解决方式：
- 用中国人最熟悉的"汉字谐音"标注发音
- 先能唱出来 → 有成就感 → 慢慢纠正发音 → 最终掌握

学习路径：
  看到歌词 → 看注音 → 能跟着唱出来 → 跟读评分
  → 发音不准 → 看标准音标 → 纠正 → 再跟读 → 评分提升
  → 成就感！→ 继续学下一首

核心理念："先唱出来，再唱准确" — 快乐 > 完美
```

### 6.2 UI展示

```
播放器字幕区（三行显示模式）：

┌───────────────────────────────────────────┐
│  I    want   to    hold   your   hand        │  ← 原文
│  爱   旺特   兔    厚的    尤尔   汉德        │  ← 注音
│  我想    牵着    你的     手                  │  ← 翻译
└───────────────────────────────────────────┘

三行可独立开关：
  ① 原文（始终显示）
  ② 中文注音（可开关，默认跟唱模式开启）
  ③ 中文翻译（可开关，默认开启）

法语示例：
┌───────────────────────────────────────────┐
│  Je    t'aime                                │  ← 法语原文
│  热    泰姆                                  │  ← 中文注音
│  我爱你                                      │  ← 中文翻译
└───────────────────────────────────────────┘
```

## 七、跟读系统 — 原音音量平衡

### 7.1 核心机制

```
跟读/跟唱统一流程（纯音频和音乐完全相同）：

1. 降低原音到跟读音量(默认60%，可调)
2. 播放当前字幕行的原声
3. 同时开始麦克风录音
4. 用户边听原声边跟读
5. 当前字幕行播放结束 → 继续录音0.5s(纯音频)/1.0s(音乐)收尾
6. 停止录音
7. 恢复原音音量到100%
8. 发送录音到声通评分(指定语言coreType)
9. 显示评分结果

关键：原音一直在播，不是"播完再录"的交替模式
→ 用户体验自然，像KTV
→ 耳机模式下录音数据纯净
```

### 7.2 跟读工具条

```
┌─ 跟读工具条 ─────────────────────────────┐
│ 🎤 录音中 03.2s                              │
│ 原音音量: ▓▓▓▓▓▓░░░░ 60%                    │
│ [🔊100%] [🔉50%] [🔇0%] ───────●─────      │
│                                               │
│ 声通评分: en.sent.eval                        │
└─────────────────────────────────────────────┘

原音音量调节的场景：
  100%: 初学，需要听清每个音跟着模仿
  50-60%: 熟练，原声做参考，自己的声音为主
  0%: 挑战，完全靠记忆唱/读，纯评分
  渐进学习: 100% → 60% → 0% 自然过渡
```

### 7.3 纯音频 vs 音乐的微小差异

| 差异点 | 纯音频跟读 | 音乐跟唱 |
|--------|-----------|---------|
| 按钮文案 | "跟读" | "跟唱" |
| 默认原音量 | 60% | 80% |
| 收尾延时 | 0.5s | 1.0s |
| 速度上限 | 2.0x | 1.5x |
| 由慢到快步进 | 0.5x→2.0x | 0.5x→1.0x |
| 声通coreType | 根据language决定 | 根据language决定 |

## 八、评分体系

### 8.1 资源评分 (resource_score)

每个音频资源有一个评分分值，记录最后一次跟读的综合表现，作为用户学习动力的核心指标。

#### 计算规则

```
评分数据来源：recording_record 表中该资源的所有跟读记录

跟读分为两种模式：
  - 逐句跟读 (scope='sentence')
  - 全文跟读/跟唱 (scope='full')

计算公式：

  情况A：仅有逐句跟读记录
    resource_score = 所有逐句跟读 overallScore 的平均值

  情况B：仅有全文跟读记录
    resource_score = 所有全文跟读 overallScore 的平均值

  情况C：同时有逐句和全文跟读记录
    sentence_avg = 所有逐句跟读 overallScore 的平均值
    full_avg     = 所有全文跟读 overallScore 的平均值
    resource_score = (sentence_avg + full_avg) / 2

  情况D：无任何跟读记录
    resource_score = null (不显示)

合理性分析：
  - 情况A：逐句练习是基础，取平均反映整体水平
  - 情况B：全文是一次性表现，取平均消除偶然性
  - 情况C：逐句和全文是不同能力维度（单句精度 vs 连贯性），
           取平均使两个维度权重相等，避免偏科
  - 取"所有记录"而非"最佳记录"：鼓励持续练习，而非刷一次高分就不管了
```

#### 展示位置

```
1. 音频列表页 — 资源卡片上显示评分标签
   ┌─────┐
   │  L  │  Let It Be
   │     │  The Beatles
   └─────┘  🎤 87分

2. 播放器顶栏 — 标题旁显示
   ← Let It Be  🎤87

3. 学习记录页 — 评分趋势图
```

#### 存储方式

评分不单独存表，每次需要展示时从 recording_record 实时计算。
原因：跟读记录会持续增加，实时计算始终反映最新状态。

可选优化：在 VideoInfo 上缓存 `lastFollowScore` 字段，
每次跟读评分后更新，避免频繁查询 recording_record。

### 8.2 评分在列表中的视觉设计

```
评分区间对应颜色和标签：

  90-100: 🟢 优秀  (绿色)
  75-89:  🟡 良好  (黄色/橙色)
  60-74:  🟠 练习中 (橙色)
  0-59:   🔴 需加强 (红色)
  null:   不显示   (无跟读记录)
```

## 九、AI评价功能

### 9.1 核心定位

```
解决的问题：让用户敢说敢唱

家长视角：孩子不只是玩app，有AI在评价指导，觉得有意义愿意买单
用户视角：不是冷冰冰的分数，而是有温度的鼓励和建议

与评分的区别：
  - 评分：客观的数字，逐词逐句的精确反馈
  - AI评价：主观的鼓励，整体的学习建议，解决"不敢开口"的心理障碍

触发方式：用户手动点击 [AI评价] 按钮
  → 不是自动触发，避免频繁调用产生成本
  → 用户感觉"我准备好听听建议了"时才点击
```

### 9.2 AI评价的生成逻辑

```
用户点击 [AI评价] → 调用边缘函数

边缘函数收到请求后：
1. 从Supabase读取该资源的字幕数据(云端)
2. 从请求中获取该资源的跟读评分记录(客户端上传)
3. 调用千问生成评价

千问Prompt：
"你是一位温暖鼓励的英语(或其他语言)学习导师。
请根据以下学习数据，给这位学习者写一段评价：

【学习内容】{资源标题}
【语言】{language}
【字幕全文】{字幕内容}

【跟读记录】
- 逐句跟读 {N} 句，平均分 {X} 分
- 全文跟读 {M} 次，平均分 {Y} 分
- 薄弱行：{低分行列表}

请从以下维度评价：
1. 鼓励：肯定学习者的努力和进步
2. 发音：指出发音上的亮点和可改进处
3. 流畅度：评价节奏和连贯性
4. 建议：给出2-3条具体的改进建议
5. 下一步：推荐接下来练习什么

语气要求：温暖、鼓励、具体、有建设性。
避免：空洞表扬、严厉批评、过于技术性的描述。"

返回格式：
{
  ok: true,
  evaluation: {
    summary: "整体评价一句话",
    encouragement: "鼓励段落",
    pronunciation: "发音评价",
    fluency: "流畅度评价",
    suggestions: ["建议1", "建议2", "建议3"],
    nextStep: "下一步建议",
    overallLevel: "beginner|elementary|intermediate|advanced",
    scoreInterpretation: "87分代表..."
  },
  costCny: ...,
  balanceAfter: ...
}
```

## 十六、核心差异化总结

```
VidLang 音频学习的五大差异化：

① 中文注音 → 30秒内能跟着唱出来 → 即时成就感
   "先唱出来，再唱准确" — 快乐 > 完美

② 声通多语言评分 → 不局限于英语 → 日语法语韩语都能学
   调用时指定语言coreType，评分维度统一

③ 原音音量可调 → 自然跟唱体验 → 边听边唱像KTV
   100%→60%→0% 渐进式挑战

④ AI评价 → 温暖鼓励+具体建议 → 解决"不敢开口"
   家长觉得有意义，愿意买单

⑤ 评分体系+学习记录 → 从工具变教育产品
   不是简单的播放器，是有温度的学习伙伴

设计原则总结：
  快乐 > 完美
  能唱出来 > 唱得标准
  先有成就感 > 再追求准确
  工具属性 → 教育属性 → 家长愿付费
```
