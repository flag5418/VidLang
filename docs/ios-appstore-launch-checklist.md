## 一、账号与资质（最紧急，阻塞后续所有步骤）

### 1.1 Apple Developer 账号 — 个人 vs 企业决策分析 ⭐

你目前是**个人注册**的 Apple Developer。是否转企业账号，这是整个上架的第一个分叉路口。

#### 个人 vs 企业完整对比

| 维度 | 个人开发者 | 企业（组织）开发者 |
|------|-----------|-----------------|
| **年费** | $99/年 | $99/年（一样） |
| **商店显示名称** | 你的真实姓名（如「Qingquan Wang」） | 公司名称（如「XX科技有限公司」） |
| **注册审核时间** | 1-2 天 | 1-2 周（需 DUNS 码） |
| **DUNS 码** | 不需要 | 需要（免费申请，邓白氏编码） |
| **税务表格** | W-8BEN（简单，个人填写） | W-8BEN-E（略复杂，需公司信息） |
| **收款账户** | 个人银行卡 | 对公账户 |
| **美元结汇** | 个人每年 5 万美金额度 | 公司账户无此限制 |
| **法律风险** | 个人无限责任 | 公司有限责任 |
| **开票能力** | 无法开具增值税专用发票 | 可开票 |
| **维护成本** | 几乎为零 | 公司年检、记账、报税（每年约 ¥2000-5000） |
| **用户信任** | 较低（个人开发者） | 较高（有实体公司背书） |
| **B2B / VPP 分发** | 不支持 | 支持批量购买和教育优惠 |
| **iMessage App** | 不支持独立发布 | 支持 |

#### 扣费分析

| 项目 | 个人 | 企业 |
|------|------|------|
| Apple 年费 | $99（约 ¥720） | $99（约 ¥720） |
| Apple 内购抽成 | 30%（年收入 <$100 万则 15%） | 同左 |
| Google Play 注册 | $25 一次性 | $25 一次性 |
| 软著 | ¥0-1000 | ¥0-1000 |
| 商标 | ¥270-1500/类 | ¥270-1500/类 |
| 服务器+域名 | ¥2000-5000/年 | ¥2000-5000/年 |
| 公司记账 | ¥0 | ¥2000-5000/年 |
| **首年总成本** | **约 ¥5000-10000** | **约 ¥8000-15000** |

#### 推广价值分析

- **个人账号**：App 搜索结果和产品页显示个人姓名，教育类 App 用户信任度打折扣。尤其你的目标用户是学生/语言学习者，家长看到「个人开发者」可能会有疑虑。
- **企业账号**：商店页显示公司名，品牌感更强。可以做 Apple Search Ads（ASA）推广，B2B 场景（学校采购）更有优势。
- **长期来看**：你计划做产品矩阵（VidLang EN → CN → KR → JP），多款 App 意味着持续收入，个人 5 万美金/年的结汇限制可能在 2-3 款 App 之后就不够用了。

#### 建议

> **强烈建议转企业账号。** 你有实体公司，DUNS 码免费申请，唯一的成本是 1-2 周等待时间 + 公司记账年费。但换来的是：品牌信任度提升、无结汇上限、法律风险隔离、长期可扩展性。教育类产品尤其需要「正规军」的形象。

| 操作 | 建议 |
|------|------|
| 现在立即行动 | 用公司营业执照申请 DUNS 码（2 周） |
| 如果个人账号已付费 | 联系 Apple Developer Support 申请账号迁移（可操作但流程较慢，建议直接新注册企业账号） |
| 如果个人账号还没付费 | 直接注册企业账号，个人账号搁置 |

**预估耗时**：2-3 周（DUNS 申请 1-2 周 + Apple 审核 1 周）

## 二、国内备案（紧急，国区上架强制要求）

### 2.1 必须完成的备案

| 备案类型 | 是否强制 | 说明 |
|---------|---------|------|
| ICP 备案 | ✅ 强制 | App 使用中国大陆服务器提供服务 |
| 网信办 APP 备案 | ✅ 强制 | 2024 年起所有上架 App 必须完成 |
| 软著（软件著作权） | ⚠️ 建议 | App Store 不强制，但国内安卓市场必备；法律维权证据 |
| ICP 许可证 | ❌ 不需要 | 教育工具类 App 不涉及经营性互联网信息服务 |
| 商标注册 | ⚠️ 强烈建议 | 防止被抢注；注册后使用 ®，申请中可用™ |

### 2.2 备案执行步骤

```
第一步：购买国内云服务器 + 域名（1 天）
├── 推荐：阿里云或腾讯云（最便宜的轻量云即可，约 ¥100/月）
├── 域名：.com 或 .cn（约 ¥50-100/年）
└── 目的：用于官网托管 + ICP 备案

第二步：ICP 备案（7-15 工作日）
├── 通过云服务商提交（阿里云/腾讯云有完整引导）
├── 材料：营业执照扫描件 + 法人身份证 + 网站负责人信息
├── 手机号需与身份证归属一致
└── 管局审核通过后获得 ICP 备案号（如「京ICP备XXXXXXXX号」）

第三步：网信办 APP 备案（1-3 工作日）
├── 在「互联网信息服务算法备案系统」提交
├── 需要：APP 名称 + Bundle ID + ICP 备案号 + 隐私政策链接
└── 审核通过后获得 APP 备案号

第四步：App Store Connect 填写备案号
└── 中国大陆区域勾选后，填入 ICP 备案号即可
```

### 2.3 关键提醒

- **服务器必须先买再备案**（备案时需要服务器 IP）
- **备案期间网站不能访问**（管局要求未备案网站关闭）
- **域名实名认证**：.cn / .com 注册后需 3-5 天实名认证通过
- **备案主体**：必须与 Apple Developer 账号主体一致（个人 → 个人备案；企业 → 企业备案）
- 如果你选择**企业账号 + 企业备案**，需要营业执照。如果你是**个人账号 + 个人备案**，则无需营业执照

**预估耗时**：2-5 周（域名实名 3-5 天 + ICP 7-15 天 + APP 备案 1-3 天）

## 三、计费系统 — 自建钱包 → Apple IAP 迁移（高优先级）

### 3.1 现状分析

VidLang 当前使用**自建预付费钱包模型**（Top-up → 消费扣费），与 iOS 审核要求冲突：

| 冲突点 | 当前实现 | iOS 要求 |
|--------|---------|---------|
| 虚拟商品购买 | 自建钱包充值 | 必须走 Apple IAP（StoreKit 2） |
| 支付 UI | 显示「余额」「充值」 | 必须展示 Apple 标准价格弹窗 |
| 收据验证 | 无 | 必须服务端验证 Apple 收据 |

> **结论**：自建钱包充值通道在 iOS 上不可行，必须迁移到 Apple IAP（in_app_purchase）。

### 3.2 迁移方案

```
现有架构                          迁移后架构
─────────                        ─────────
用户 → 充值页面 → 钱包余额       用户 → Apple IAP 弹窗 → Apple 收款
                                         ↓
                                    收据验证 Edge Function
                                         ↓
                                    钱包余额增加（后端入账）
```

**保留不变**：消费扣费逻辑（AI 查词/翻译/对话时从余额扣费）、余额永不过期策略、wallet_ledger 表结构。

**需要改动**：

| 文件 | 改动内容 |
|------|---------|
| `pubspec.yaml` | 添加 `in_app_purchase` 依赖 |
| `lib/services/iap_service.dart` | 新建 IAP 服务（StoreKit 2） |
| `lib/views/profile/topup_page.dart` | 对接真实 IAP 支付流程 |
| `supabase/functions/verify_purchase/` | 新建收据验证 Edge Function |
| `supabase/functions/billing-center/` | 修改入账逻辑区分 IAP 来源 |

### 3.3 IAP 商品配置

在 App Store Connect 创建 3 个 Consumable（消耗型）Product ID：

| Product ID | 价格 | 到账余额 | 说明 |
|-----------|------|---------|------|
| `vidlang.topup.10` | ¥10 | ¥10 | 入门体验 |
| `vidlang.topup.50` | ¥50 | ¥55（+10%） | 进阶包 |
| `vidlang.topup.100` | ¥100 | ¥120（+20%） | 超值包 |

**注意**：
- Consumable 类型（充值类）不是 Auto-Renewable（订阅类）
- 全球上架时 Apple 自动按汇率转换价格，无需自己处理多币种
- 审核时可能需要提供恢复购买的 UI

### 3.4 全球价格策略

| 地区 | Tier 1 (入门) | Tier 2 (进阶) | Tier 3 (超值) |
|------|-------------|-------------|-------------|
| 中国大陆 | ¥10 | ¥50 | ¥100 |
| 美国 | $0.99 | $4.99 | $9.99 |
| 欧洲 | €0.99 | €4.99 | €9.99 |
| 日本 | ¥120 | ¥600 | ¥1200 |

> Apple App Store Connect 提供全球价格矩阵，只需设定一个基准 Tier，其他地区自动映射。

**预估耗时**：2-3 周（开发 1.5 周 + 调试 0.5 周 + App Store Connect 配置 Sandbox 测试）

## 四、法律合规文件（高优先级，审核必须）

### 4.1 隐私政策（Privacy Policy）

App Store 审核强制要求，必须在 App 内和官网上都可访问。

**必须涵盖的内容**：

1. **数据收集清单**
   - 本地存储：视频/字幕/学习记录（仅存在设备上）
   - 云端同步：用户配置、学习进度（Supabase PostgreSQL）
   - AI 调用：文本/音频发送至阿里云 DashScope 和 DeepSeek API
   - 论坛数据：用户发布的帖子/评论

2. **第三方 SDK 声明**
   - Supabase（Auth + Database + Edge Functions）
   - 阿里云 DashScope（TTS 语音合成）
   - 声通（语音识别 STT）
   - DeepSeek API（AI 查词/翻译/对话）
   - in_app_purchase（Apple IAP）

3. **用户权利说明**
   - 数据访问/导出/删除权利
   - 联系方式

4. **儿童隐私**（因 4+ 分级）
   - COPPA（美国）合规声明
   - 不主动收集 13 岁以下儿童个人信息

**操作**：
- 编写一份标准的 HTML 隐私政策页面放在官网
- App 内设置页面提供链接跳转
- App Store Connect 填写 Privacy Nutrition Label（数据收集类型逐项勾选）

**预估耗时**：2-3 天撰写 + 1 天部署

### 4.2 用户协议（Terms of Service）

比隐私政策简单，但同样必须：

- 明确用户与开发者之间的权利义务
- 免责声明（AI 生成内容不保证 100% 准确）
- 知识产权声明
- 终止条款

**预估耗时**：1 天撰写 + 半天部署

### 4.3 年龄分级

**建议选择 4+**，理由：

- 教育类 App，内容无暴力/色情/赌博
- 4+ 最大化用户覆盖，不受家长控制和 Screen Time 限制
- 论坛 UGC 内容需配合内容审核机制 + 举报功能（与审核团队沟通时主动声明有审核机制）

### 4.4 GDPR 合规（全球发布）

如果你选择全球 175 国同时上架，需要：

- Cookie 弹窗（如有网页版）
- 用户数据删除请求处理流程
- 数据保护官（DPO）联系方式（可用邮箱代替）

如果只上架中国大陆 + 美国，暂时不需要 GDPR。

**预估耗时**：2 天（基于标准模板修改）

## 五、产品打磨（中优先级，但影响审核通过率）

### 5.1 审核阻塞项（P0）

| 任务 | 说明 | 状态 |
|------|------|------|
| 内置示例学习包 | 1 个短视频（2-3 分钟中英字幕）+ 1-2 篇 AI 分级阅读 | ☐ |
| 空状态引导 | 首次打开无内容时的引导（导入本地 / 体验示例） | ☐ |
| 余额永不过期标注 | 充值页 + 钱包页醒目展示 | ☐ |
| 学习闭环打通 | 播放→查词→跟读→记录→单词本 全链路验证 | ☐ |
| 网络错误友好页 | 网络断开、AI 超时、余额不足等场景的提示页 | ☐ |

### 5.2 UGC 论坛特殊处理（重要）

项目含社区论坛功能，这对 iOS 审核是关键风险点。审核团队会关注：

1. **内容审核机制**：是否有能力过滤违规内容？
2. **举报功能**：用户是否可以举报违规帖子？
3. **用户屏蔽**：是否可以屏蔽其他用户？
4. **内容过滤**：是否过滤色情/暴力/仇恨言论？

**建议**：
- 在审核备注中主动声明有内容审核策略（参考 `forum-design.md` 中的合规章节）
- 论坛功能可以设置为审核期关闭，审核通过后再通过配置开关开启
- 准备一个审核专用的演示账号，其论坛内容为干净的示例数据

### 5.3 审核注意事项

- **App 完整性**：提交的 Build 不能崩溃、不能有明显 Bug
- **元数据准确**：截图与实际功能一致，描述不夸大
- **隐私权限说明**：Info.plist 中的权限描述文案清晰、准确（你的已经配置了，很好）
- **硬编码无测试入口**：不要有「测试模式」「开发模式」的隐藏入口
- **ATS 配置**：你的 Info.plist 中 `NSAllowsArbitraryLoads=true` 可能需要向审核说明原因（AI API 调用 HTTP 端点）

**预估耗时**：2-3 周

## 七、TestFlight + 审核流程（中优先级）

### 7.1 TestFlight 配置

```
1. Xcode → Product → Archive（生成 .xcarchive）
2. Organizer → Distribute App → App Store Connect
3. App Store Connect → TestFlight → 创建内部测试组
4. 邀请测试者（最多 100 人，内部测试无需审核）
5. 收集崩溃日志 + 用户反馈
6. 至少 1-2 轮测试 → 修复 → 重新 Build
```

### 7.2 审核提交 Checklist

| 检查项 | 确认 |
|--------|------|
| Bundle ID 已配置且与 App ID 匹配 | ☐ |
| 版本号（CFBundleShortVersionString）正确 | ☐ |
| IAP Product ID 已在 App Store Connect 配置且状态为「Ready to Submit」 | ☐ |
| 隐私政策 URL 可访问 | ☐ |
| 用户协议 URL 可访问（如适用） | ☐ |
| ICP 备案号已填写 | ☐ |
| 隐私标签已填写 | ☐ |
| 年龄分级已设置（4+） | ☐ |
| App 不崩溃、不闪退 | ☐ |
| 演示账号已准备（如需登录） | ☐ |
| 截图与实际功能一致 | ☐ |
| 无隐藏的测试模式入口 | ☐ |
| export-compliance（加密）已填写 | ☐ |

### 7.3 审核时间线

- **首次提交**：通常 24-48 小时
- **如有问题被拒**：根据反馈修改后重新提交，可能再 24-48 小时
- **如被拒 3 次以上**：可能需要电话联系审核团队说明情况
- **加急审核**：每年有 2 次加急机会（Expedited Review）

**预估耗时**：1-3 周（含 TestFlight 测试 1-2 周 + 审核 2-5 天）

## 八、全球发布额外事项（低优先级，可在国区上架后逐步推进）

### 8.1 多语言本地化

|--------|------|--------|

| P0 | 英文 | 全球通用 |

### 8.2 地区合规差异

| 地区 | 额外要求 |
|------|---------|
| **欧盟** | GDPR、Cookie 同意、DSA（数字服务法）合规 |
| **加州** | CCPA（加州消费者隐私法案） |
| **韩国** | 游戏类需 GRAC 分级（教育类通常豁免） |
| **日本** | 特定商取引法标注 |
| **巴西** | LGPD（巴西通用数据保护法） |

### 8.3 支付告知书（中国大陆额外要求）

iOS 国区上架时，中国大陆要求在 App 内购买前弹窗展示：
- "本 App 内购买使用 Apple 的支付系统"
- 具体支付金额
- 取消/确认按钮

这个需要在前端代码中实现。

## 十、关键决策速查表

| 决策点 | 推荐方案 | 核心理由 |
|--------|---------|---------|
| 个人 vs 企业 | **企业** | 品牌信任度、无结汇限制、法律责任隔离、支持产品矩阵 |
| 年龄分级 | **4+** | 教育类 App，最大化用户覆盖 |
| 支付方案 | **Apple IAP** | iOS 强制要求，平台自动处理汇率/税务 |
| 充值档位 | **¥10 / ¥50 / ¥100** | Consumable IAP，叠加赠送策略 |
| 备案主体 | **企业** | 与 Apple Developer 企业账号一致 |
| 多语言首发 | **简体中文 + 英文** | 覆盖最大市场 |
| 论坛首版 | **审核期关闭** | 降低审核风险，通过后配置开关打开 |
| 全球价格 | **Apple Tier 自动映射** | 无需手动维护多币种定价 |

## 十一、风险预警

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| DUNS 码申请超时 | Apple 企业账号延迟 | 提前 2 周申请，每周跟进 |
| ICP 备案被驳回 | 国区无法上架 | 确保材料准确（营业执照清晰、手机号一致） |
| IAP 对接 Bug 多 | 审核被拒 | Sandbox 测试充分，至少覆盖 3 种金额档位 |
| 论坛 UGC 审核卡住 | 被拒或要求 17+ 分级 | 审核期间关闭论坛，备注说明有审核机制 |
| 公司注销风险 | 账号被冻结 | 保持公司正常年检 |
| 汇率波动 | 全球收入波动 | 可接受，Apple 自动处理 |
